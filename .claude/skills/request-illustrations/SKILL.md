# 삽화 화풍 분석·생성 요청서 만들기

기존 삽화의 화풍을 분석해 **스타일 가이드**를 만들고, 삽화가 필요한 동화에 대해 이미지 생성 도구에 바로 붙여 쓸 **완성형 프롬프트 요청서**를 만드는 스킬이다. 실제 작업은 **`illustration-director` 에이전트**에 위임한다.

**중요: 이 스킬은 이미지를 생성하지 않는다.** 요청서의 프롬프트로 이미지를 별도 생성해 `assets/images/`에 정확한 파일명으로 넣으면 사이트에 자동 반영된다.

## 절차

1. **요청 범위 확정** (부족한 정보만 간단히 확인):
   - **대상**: 특정 동화(slug 또는 제목) / 누락 이미지가 있는 동화 전부 / 화풍 분석만
   - **범위**: 표지(`{slug}-story-cover.png`)만, 본문 장면(`01~10`)만, 또는 전체
   - 사용자가 "누락된 거 다 해줘"라고 하면 추가 질문 없이 스캔부터 진행.

2. **에이전트 실행**: `illustration-director` 에이전트를 Agent 도구로 실행한다. 프롬프트에 대상·범위를 명시한다. 에이전트는:
   - **화풍은 이미 분석 완료**(`docs/art-style-guide.md`, 에이전트 프롬프트에도 프리셋 내장). 실행 시에는 대상 동화의 기존 삽화 + 같은 계열 대표 삽화를 **직접 열람**해 캐릭터 외형을 파악하고 가이드와 실물의 일치를 확인한다(불일치하거나 재분석 요청 시에만 가이드 갱신).
   - `pages/family/*-story.html` ↔ `assets/images/` 대조로 누락 이미지 스캔
   - 동화별 요청서 `docs/illustration-requests/{slug}.md` 생성 (프리셋+캐릭터+장면이 조립된 완성 프롬프트, 표지 포함)

3. **여러 동화일 때**: 요청서는 동화당 파일이 분리돼 있고 가이드는 이미 확정돼 있어, 에이전트를 **병렬 실행해도 충돌 없다**(가이드 재분석이 필요한 경우만 먼저 단독으로 갱신 후 병렬).

4. **보고**: 화풍 분석 요약, 누락 현황 표, 생성된 요청서 파일 목록, 다음 단계(이미지 생성 → `assets/images/` 저장 → 자동 반영)를 정리해 보고한다.

## 주의

- **저작권**: 프롬프트에 특정 작가·스튜디오·작품 스타일("Ghibli style" 등)과 실존 캐릭터 명칭을 절대 넣지 않는다. 일반 묘사만 사용.
- 파일명 규칙: 본문 장면 `{slug}-story-01.png ~ -10.png`, 허브 표지 `{slug}-story-cover.png`. 이름이 정확해야 자동 반영된다.
- `docs/illustration-prompts.md`는 story-builder가 관리하는 시트라 이 스킬에서 수정하지 않는다(참조만).
- 삽화가 완성되어 사이트 반영(허브 카드·카탈로그 복원 등)이 필요하면 별도 요청으로 처리한다.
