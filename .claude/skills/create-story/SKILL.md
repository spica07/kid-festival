# 새 그림동화 만들기

새 그림동화 1편을 기존 동화들과 **동일한 방식**으로 제작·등록하는 스킬이다. 실제 제작은 **`story-builder` 에이전트**에 위임한다.

**중요: 삽화(PNG)는 이 스킬에서 만들지 않는다.** 그림은 나중에 별도로 그려 `assets/images/`에 추가된다. 이 스킬은 **글 + 화면 구성 + 영어 번역 + 삽화용 프롬프트**까지만 만들고, 이미지 자리는 비워 둔다.

## 절차

1. **요구사항 확정** (사용자에게 부족한 정보만 간단히 확인):
   - **주제/교훈** (감정 조절·나눔·정직·협동·자연 보호 등) 또는 **전래동화 각색** 여부
   - **주인공**(동물/아이, 이름·성격)과 **분위기**
   - (선택) 원하는 **slug**(영문). 없으면 에이전트가 내용에 맞게 정함
   - 사용자가 premise를 충분히 주면 추가 질문 없이 진행. 한 번에 여러 편을 원하면 편수를 확인.

2. **중복 확인**: `pages/family/` 와 `picture-story-hub.html` 에서 같은 주제/slug가 이미 있는지 가볍게 점검.

3. **에이전트 실행**: `story-builder` 에이전트를 Agent 도구로 실행한다. 프롬프트에 위 요구사항(주제·주인공·분위기·slug)과 "삽화는 만들지 말 것"을 명시한다. 에이전트는 6곳을 처리한다:
   - `pages/family/{slug}-story.html` 생성 (정적 10 스프레드)
   - `assets/js/pages/story-reader.js` 의 `ENGLISH_STORIES`에 영어 항목 추가
   - `pages/family/picture-story-hub.html` 에 카드 추가
   - `docs/illustration-prompts.md` 에 10장 프롬프트 섹션 추가
   - `sw.js` 캐시 버전 +1
   - `node --check`로 검증

4. **여러 편일 때**: 동화별로 에이전트를 **병렬 실행**해도 되지만, `story-reader.js`·hub·`sw.js`·`docs`는 **공유 파일**이라 동시 Edit 시 충돌한다. 병렬 시에는 에이전트에게 **본문·HTML·프롬프트 초안까지만** 시키고, 공유 파일(영어 항목·허브 카드·캐시·프롬프트 시트) 반영은 **메인에서 취합해 한 번에** 한다.

5. **검증**: `node --check C:\kid\assets\js\pages\story-reader.js` 통과 확인. (선택) 로컬 서버로 페이지를 띄워 캐러셀·한/영 토글·읽기가 동작하는지 확인한다. 이미지는 아직 없으므로 깨진 이미지로 보이는 게 정상이다.

6. **보고**: 만든 동화(제목·slug·주제·English title), 수정한 파일 체크리스트, 그리고 **별도로 그려야 할 삽화 10장 목록**(`{slug}-story-01~10.png` + 각 장면 설명)을 표로 정리해 보고한다.

## 주의

- 신규 동화는 **정적 HTML + `story-reader.js`** 방식이 표준이다. 데이터 기반 방식(과거 태양계 동화의 `solar-stories.js`, 2026-06 삭제됨)으로 만들지 않는다.
- 화면 구성(툴바·캐러셀·읽기·한/영 토글)은 `story-reader.js`가 자동 처리하므로, HTML에는 정적 스프레드만 넣으면 된다.
- 영어 번역은 모든 신규 동화에 **반드시 포함**(한/영 토글 일관성). 상세 형식·스키마·HTML 템플릿은 `story-builder` 에이전트 정의에 정리돼 있다.
- **저작권**: 실존 작품의 제목·캐릭터명 사용 금지, 유명작과 설정+캐릭터+전개 동시 겹침 금지, 삽화 프롬프트에 특정 작가·스튜디오 스타일 지정 금지. 상세 규칙은 `story-builder` 에이전트의 "스토리 작성 규칙 7"에 있다.
- 삽화 생성·추가는 이 스킬의 범위가 아니다(별도 작업).
