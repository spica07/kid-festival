# 꼬마 축제 페이지 업데이트

이 스킬은 **`assets/data/festivals.js` 의 `window.KID_FESTIVALS` 배열**(행사 데이터, 약 430건)을 최신으로 유지한다. 실제 작업은 **`festival-updater` 에이전트**에 위임한다.

> 참고: `assets/js/pages/kid-festival.js`는 데이터가 아니라 달력 계산·실내외 분류 등 **렌더링 로직**이며, 실내외 예외(`VENUE_OVERRIDE`)·기준 월(`currentYear`/`currentMonth`)만 거기 있다.

## 절차

1. **기간 확정**: 환경의 오늘 날짜를 기준으로 대상 기간을 정한다 — **현재 월 + 다음 3개월(총 4개월)**. (예: 오늘이 6월이면 6·7·8·9월) 사용자가 특정 월/분기를 지정했으면 그것을 따른다.

2. **에이전트 실행**: `festival-updater` 에이전트를 Agent 도구로 실행한다. 프롬프트에 다음을 명시:
   - **데이터 파일은 `assets/data/festivals.js`의 `window.KID_FESTIVALS` 배열**임을 분명히 한다(kid-festival.js 아님).
   - 대상 기간(위에서 정한 4개월)과 지역(서울·경기·인천), 대상 연령(5~7세).
   - **세 가지 임무**: (a) 공공데이터 최신본 재수집, (b) 기존 행사 일정·장소 재확인·갱신(임박 행사는 교차검증 필수), (c) 기간 내 신규 행사 검색·추가.

   - **(a) 공공데이터는 매번 그 시점 최신본을 새로 받는다.** 전국문화축제표준데이터·TourAPI·서울 열린데이터광장 응답이나 이전 실행에서 저장해둔 로컬 파일을 재사용하지 않는다 — 표준데이터는 분기 단위로 갱신되므로, 오래된 캐시를 쓰면 그 사이 지자체가 발표한 최신 일정을 놓친다.

   - **(b) 임박 행사(오늘 기준 1개월 이내)는 표준데이터만으로 확정하지 않고 날짜·장소를 반드시 교차검증한다.** 표준데이터·지자체 SNS 그래픽은 "공식"이지만 "최신"이 아닐 수 있다 — 실제로 2026-09-10에 **잠원나루축제**가 표준데이터엔 9월 19일(작년 제11회 패턴이 그대로 남은 값)로 등록돼 있었는데, 실제 올해(제12회)는 서초구 당일 보도자료 기준 9월 12일이었다. 검증 방법:
     - `WebSearch`로 `"<행사명> <대상연도>"` 검색 → 결과에 섞인 **회차(제N회)와 기사 작성일을 반드시 대조**해 작년 기사를 올해 것으로 착각하지 않는다.
     - 유력한 기사/공식 공지를 `WebFetch`로 열어 정확한 날짜·요일·**장소**·시간을 확인한다(날짜만 보고 장소를 놓치지 않는다 — 매년 다른 공원으로 옮기는 행사도 있다).
     - 요일-날짜 정합성도 기계적으로 한 번 걸러본다(`festival-date-checker` 에이전트의 방법 참고: `py`로 실제 요일을 계산해 `(요일)` 표기와 대조).
     - 이 절차는 `check-festival-dates` 스킬 / `festival-date-checker` 에이전트와 같은 방법론이다. 대상 행사가 많으면 그쪽 스킬로 별도 재검증 라운드를 돌려도 된다.
   - 1개월 이후 행사는 기존처럼 표준데이터·공식 페이지 확인으로 충분하다(모든 행사를 언론 교차검증하면 비용이 과도하다).

   - **(c) 검색 전략 (계층형 — 매우 중요)**: 대부분의 한국 축제 포털 **목록**(구석구석 kfes·서울문화포털·경기관광포털)은 JS로 렌더링돼 `WebFetch`로는 빈 껍데기만 나온다(펀서울·각 상세 페이지는 정적으로 됨). `WebSearch`도 미국 기반이라 소규모 지역 행사를 잘 못 찾는다. 따라서 **다음 순서로** 지시한다: ① **공개 정부 API로 축제 목록을 열거**(서울 열린데이터광장 `culturalEventInfo`, 한국관광공사 TourAPI `searchFestival2`, 전국문화축제표준데이터) → ② 얻은 후보의 **공식/kfes·펀서울 상세 페이지를 WebFetch로 검증**(일정·요금·연령·링크) → ③ **펀서울 목록(정적)** 직접 순회로 보완 → ④ API 누락분은 **Claude in Chrome 브라우저 자동화**로 렌더된 목록 추출 → ⑤ 보조로 `WebSearch`를 `go.kr`/`or.kr` 도메인 한정. (엔드포인트·지역코드 등 상세는 `festival-updater` 에이전트 정의 참조.) API는 인증키(data.go.kr serviceKey·서울 열린데이터 인증키)가 필요하니, 없으면 사용자에게 요청하도록 한다.
   - **병렬 실행 시 주의**: 지역별로 나눌 때 여러 에이전트가 *똑같은 정적 fetch 실패를 반복*하지 않도록, 포털별 역할("API 열거 / 정적 상세 검증 / 브라우저 자동화")을 나눠 지시한다. **임박 행사 교차검증(위 (b))도 병렬로 나눌 때는 검색·확인까지만 시키고, 최종 Edit는 메인에서 취합** — 동시에 여러 에이전트가 같은 배치를 몇십 건씩 웹서치하면 세션 사용량 한도(월 한도 등)에 먼저 걸릴 수 있으니, 배치 크기를 한 번에 감당 가능한 수준(수십 건 이내)으로 조절한다.
   - 모든 날짜·요금·장소는 공식/지자체 출처로 확인하고, 추측 금지, 중복 추가 금지(추가 전 `festivals.js`에서 title Grep).
   - 작업 후 데이터 파싱 검증(아래 3번).

3. **검증**: 에이전트 작업 후 데이터 파일이 정상 파싱되는지 확인한다 — `node -e "global.window={}; require('C:/blog_writing/kid-festival/assets/data/festivals.js'); console.log(window.KID_FESTIVALS.length)"`. 렌더링 파일을 건드렸다면 `node --check C:\blog_writing\kid-festival\assets\js\pages\kid-festival.js` 도 확인. 실패하면 원인을 찾아 수정한다.

4. **(선택) 미리보기**: 사용자가 원하면 로컬에서 페이지를 띄워 카드/달력에 신규·갱신 행사가 제대로 보이는지 확인한다.

5. **보고**: 다음을 표로 정리해 사용자에게 보고한다.
   - ✅ 일정·**장소**가 **갱신**된 기존 행사 (변경 전 → 후 · 근거 출처)
   - 🔧 **임박 행사 교차검증에서 표준데이터와 다르게 확정된 항목** (표준데이터 값 → 실제 값 · 회차 · 근거 URL) — 위 (b)의 결과
   - 🆕 **추가**된 신규 행사 (제목 · 지역 · 기간 · 요금 · 출처 URL)
   - ⚠️ **확인 필요/불확실** 항목 (일정 미발표, 출처 불명확 등)

## 주의

- 행사 **삭제나 대폭 변경은 사용자 확인 후** 진행한다.
- 데이터 형식·코드 스타일은 기존 그대로 유지하고, 불필요한 대량 재정렬은 하지 않는다.
- 스키마·달력 계산 규칙·실내외 분류 등 상세 규칙은 `festival-updater` 에이전트 정의에 정리돼 있다.
