# 꼬마 축제 페이지 업데이트

이 스킬은 **`assets/data/festivals.js` 의 `window.KID_FESTIVALS` 배열**(행사 데이터, 약 200건)을 최신으로 유지한다. 실제 작업은 **`festival-updater` 에이전트**에 위임한다.

> 참고: `assets/js/pages/kid-festival.js`는 데이터가 아니라 달력 계산·실내외 분류 등 **렌더링 로직**이며, 실내외 예외(`VENUE_OVERRIDE`)·기준 월(`currentYear`/`currentMonth`)만 거기 있다.

## 절차

1. **기간 확정**: 환경의 오늘 날짜를 기준으로 대상 기간을 정한다 — **현재 월 + 다음 2개월(총 3개월)**. (예: 오늘이 6월이면 6·7·8월) 사용자가 특정 월/분기를 지정했으면 그것을 따른다.

2. **에이전트 실행**: `festival-updater` 에이전트를 Agent 도구로 실행한다. 프롬프트에 다음을 명시:
   - **데이터 파일은 `assets/data/festivals.js`의 `window.KID_FESTIVALS` 배열**임을 분명히 한다(kid-festival.js 아님).
   - 대상 기간(위에서 정한 3개월)과 지역(서울·경기·인천), 대상 연령(5~7세).
   - 두 가지 임무: (a) 기존 행사 일정 웹 재확인·갱신, (b) 기간 내 신규 행사 검색·추가.
   - **검색 전략**: `WebSearch`는 미국 기반이라 한국 지역 행사를 잘 못 찾는다. **펀서울(festival.seoul.go.kr)·서울문화포털·구석구석 축제달력(visitkorea kfes)·경기/인천 관광포털 등 한국 축제 포털 목록 페이지를 WebFetch로 직접 순회**해 후보를 모으고, 각 공식 상세 페이지로 일정·요금을 확인하도록 지시한다.
   - 모든 날짜·요금은 공식/지자체 출처로 확인하고, 추측 금지, 중복 추가 금지(추가 전 `festivals.js`에서 title Grep).
   - 작업 후 데이터 파싱 검증(아래 3번).
   - 규모가 크면 지역별로 에이전트를 **병렬 실행**(서울/경기/인천 각각)해 효율을 높여도 된다. 단 같은 파일을 동시에 Edit하면 충돌하므로, 병렬은 "검색·수집"까지만 시키고 **최종 Edit는 메인에서 취합해 한 번에** 반영한다.

3. **검증**: 에이전트 작업 후 데이터 파일이 정상 파싱되는지 확인한다 — `node -e "global.window={}; require('C:/kid/assets/data/festivals.js'); console.log(window.KID_FESTIVALS.length)"`. 렌더링 파일을 건드렸다면 `node --check C:\kid\assets\js\pages\kid-festival.js` 도 확인. 실패하면 원인을 찾아 수정한다.

4. **(선택) 미리보기**: 사용자가 원하면 로컬에서 페이지를 띄워 카드/달력에 신규·갱신 행사가 제대로 보이는지 확인한다.

5. **보고**: 다음을 표로 정리해 사용자에게 보고한다.
   - ✅ 일정이 **갱신**된 기존 행사 (변경 전 → 후)
   - 🆕 **추가**된 신규 행사 (제목 · 지역 · 기간 · 요금 · 출처 URL)
   - ⚠️ **확인 필요/불확실** 항목 (일정 미발표, 출처 불명확 등)

## 주의

- 행사 **삭제나 대폭 변경은 사용자 확인 후** 진행한다.
- 데이터 형식·코드 스타일은 기존 그대로 유지하고, 불필요한 대량 재정렬은 하지 않는다.
- 스키마·달력 계산 규칙·실내외 분류 등 상세 규칙은 `festival-updater` 에이전트 정의에 정리돼 있다.
