# 꼬마 축제 링크·길찾기 점검

이 스킬은 **`assets/data/festivals.js`의 `window.KID_FESTIVALS` 배열**(약 430건)의 외부 링크와 네이버 길찾기 동작을 점검한다. 실제 작업은 **`festival-link-checker` 에이전트**에 위임한다.

점검 대상:
- **홈페이지 URL**: 각 행사의 `web` · `detail.reservationUrl` · `detail.sourceUrl` (도메인+경로 기준 중복 제거 후 점검)
- **네이버 길찾기**: `kid-festival.js`/`festival-detail.js`의 `mapQuery` 규칙(`mapName` 최우선 → 박물관·도서관·테마파크는 `title` → 그 외는 가운뎃점 제거한 `location`)으로 만든 검색어가 네이버 지도에서 실제 장소를 찾는지

## 절차

1. **범위 확정**: 기본은 전체 행사. 사용자가 특정 지역·기간·최근 추가분만 지정했으면 그것을 따른다.

2. **에이전트 실행**: `festival-link-checker` 에이전트를 Agent 도구로 실행한다. 프롬프트에 다음을 명시:
   - 데이터 파일은 `assets/data/festivals.js`의 `window.KID_FESTIVALS` 배열임을 분명히 한다.
   - 점검 범위(전체 또는 지정 범위)와 두 가지 임무: (a) 홈페이지 URL 생존 점검, (b) 네이버 길찾기 검색 결과 검증.
   - 규모가 크면 지역별(서울/경기/인천+기타)로 **병렬 실행**해도 된다. 단 병렬일 때는 각 에이전트에 **"점검만, 수정 금지(check-only)"**를 명시하고, 수정은 결과를 취합해 **메인에서 한 번에** 반영한다(같은 파일 동시 Edit 충돌 방지). 단일 에이전트면 에이전트 정의의 수정 규칙(공식 확인된 대체 URL 교체 등)에 따라 자율 수정을 허용해도 된다.
   - 봇 차단(403)·SPA 특성 때문에 "응답 없음 = 깨짐"이 아님을 에이전트가 알고 있다(에이전트 정의에 판정 기준 있음) — 모호한 항목은 "수동 확인 필요"로 받는다.

3. **수정 반영**(있는 경우): 깨진 URL의 공식 대체 URL 교체, 길찾기 실패 행사에 검증된 `mapName` 추가(표시용 `location`/`title`은 유지)를 반영한다. 행사 삭제나 `mapQuery` 로직 변경은 **사용자 확인 후**에만.

4. **검증**: 데이터 파일을 수정했다면 정상 파싱 확인 — `node -e "global.window={}; require('C:/blog_writing/kid-festival/assets/data/festivals.js'); console.log(window.KID_FESTIVALS.length)"` (건수가 변하지 않아야 정상). 렌더링 파일을 건드렸다면 `node --check` 도 확인.

5. **보고**: 다음을 표로 정리해 사용자에게 보고한다.
   - ❌ **깨진 홈페이지 URL** (행사 · 기존 URL · 증상 · 대체 URL 또는 "대체 불가")
   - ❌ **길찾기 실패** (행사 · 검색어 · 증상 · 제안 검색어)
   - ⚠️ **수동 확인 필요** (봇 차단, 타지역 매칭 의심 등)
   - 🔧 **수정 적용 내역** (변경 전 → 후)
   - 📊 요약 통계 (점검/정상/실패/의심 건수)

## 주의

- 네이버 지도 API 호출은 비공식 내부 API라 차단될 수 있다 — 차단되면 해당 항목은 실패가 아니라 "수동 확인 필요"로 처리한다.
- 링크가 깨졌다고 행사를 삭제하지 않는다(삭제는 사용자 확인 후).
- 판정 기준·캘리브레이션 방법 등 상세 규칙은 `festival-link-checker` 에이전트 정의에 정리돼 있다.
