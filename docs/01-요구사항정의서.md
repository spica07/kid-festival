## 1. 개요

### 1.1 서비스 정의
서울·경기·인천에 사는 **미취학(만 5~7세) 아이와 부모님**을 위해 **놀이 · 나들이 · 학습 · 힐링** 정보를 한곳에 모은 웹 서비스다. 흩어져 있던 어린이 행사·체험 정보와 가정 학습 콘텐츠를, 부모가 보기 좋게 한 화면에서 둘러볼 수 있도록 한다.

### 1.2 목표
- 주말 나들이거리(어린이 축제·체험)를 **월 단위 달력**으로 빠르게 탐색
- 집에서 즐기는 **영어 · 수학 · 한글** 가정 학습을 캐릭터·놀이 형태로 제공
- 아이의 **학습 진행 상황을 기기에 저장**해 이어서 진행
- 육아로 지친 부모를 위한 **힐링·가이드·진학 정보** 제공

### 1.3 핵심 특성
- **서버·DB·로그인 없음**: 순수 정적 HTML/CSS/JS로 구성
- **개인정보 미수집**: 진행 상황 등 모든 데이터는 `localStorage`(해당 기기 브라우저)에만 저장
- **모바일 우선**: 부모가 휴대폰으로 사용하는 상황을 기본 전제

## 3. 기능 요구사항 (FR)

### 3.1 공통 / 내비게이션
| ID | 요구사항 | 우선순위 |
|----|----------|:---:|
| FR-N1 | 메인(`index.html`)은 **상단 탭바 + iframe** 구조로, 탭 전환 시 페이지 새로고침 없이 해당 코너를 표시한다 | 必 |
| FR-N2 | 자주 쓰지 않는 메뉴(가이드·로드맵·공모전)는 **더보기(⋯)** 드롭다운에 묶는다 | 必 |
| FR-N3 | 영어/수학/한글/소개는 **아이콘 탭**(🔤/🔢/가/ℹ️)으로 제공한다 | 必 |
| FR-N4 | 자식 페이지(iframe·소개)에서 부모창의 `showSiteTab(target)`을 호출해 탭을 전환할 수 있다 | 必 |
| FR-N5 | 단독(직접 URL)으로 열렸을 때는 메인으로 이동하는 폴백을 제공한다 | 中 |

### 3.2 동네 축제 (나들이 달력)
| ID | 요구사항 | 우선순위 |
|----|----------|:---:|
| FR-F1 | 서울·경기·인천의 어린이 축제·체험·나들이 정보를 **월별**로 제공한다 | 必 |
| FR-F2 | 이번 달·다음 달 등 시점 기준으로 행사를 탐색할 수 있다 | 必 |
| FR-F3 | 행사 정보는 변동 가능함을 명시하고 **공식 홈페이지 확인**을 안내한다 | 必 |
| FR-F4 | 행사 데이터는 주기적으로 갱신한다(운영 스킬 `update-festivals` 연계) | 中 |

### 3.3 학습 — 영어 / 수학 / 한글
| ID | 요구사항 | 우선순위 |
|----|----------|:---:|
| FR-L1 | 각 과목은 **허브 페이지**에서 코스 목록을 카드로 보여준다 | 必 |
| FR-L2 | 영어는 **캐릭터(동물 선생님) 6종 × 30일 = 총 180일** 코스로 구성한다 | 必 |
| FR-L3 | 수학은 수·도형·패턴·측정·자료·사고력 등 **영역별 30일 코스** 및 7세 코스를 제공한다 | 必 |
| FR-L4 | 한글은 문해력·어휘·문장·받아쓰기 등 **30일/7세 코스**와 글씨 연습을 제공한다 | 必 |
| FR-L5 | 코스별 **일자(Day) 단위 학습** 화면을 제공한다 | 必 |
| FR-L6 | 완료한 일자를 체크해 **진행률(전체/코스)**을 표시한다 | 必 |
| FR-L7 | '완료한 과정 보이기/숨기기' 토글을 제공한다 | 中 |

### 3.4 진행 상황 저장
| ID | 요구사항 | 우선순위 |
|----|----------|:---:|
| FR-S1 | 학습 진행 상황은 `localStorage`에 저장하고 재방문 시 복원한다 | 必 |
| FR-S2 | 데이터는 **서버로 전송하지 않으며** 해당 기기에만 보관됨을 소개 페이지에 명시한다 | 必 |
| FR-S3 | 방문기록·사이트 데이터 삭제 또는 시크릿 모드 사용 시 데이터가 사라질 수 있음을 안내한다 | 中 |

### 3.5 그림동화
| ID | 요구사항 | 우선순위 |
|----|----------|:---:|
| FR-T1 | 그림동화 허브에서 여러 동화(우주·바다·공룡·기차 등)를 선택할 수 있다 | 必 |
| FR-T2 | 동화는 **페이지 단위 리더(story-reader)**로 한 장씩 넘겨 본다 | 必 |
| FR-T3 | 각 동화는 제목·소개·삽화·본문으로 구성한다 | 必 |

| ID | 요구사항 | 우선순위 |

## 4. 비기능 요구사항 (NFR)

| ID | 분류 | 요구사항 |
|----|------|----------|
| NFR-1 | 보안 | 모든 페이지에 **CSP(Content-Security-Policy)** 헤더를 적용한다 (`default-src 'self'`, 외부 스크립트 차단, 폼 전송 차단 등) |
| NFR-2 | 개인정보 | 회원가입·로그인·서버 전송 없이 운영하며 개인정보를 수집하지 않는다 |
| NFR-3 | 반응형 | 모바일(≤600px) 우선으로 동작하고 태블릿·데스크톱에서도 정상 표시한다 |
| NFR-4 | 접근성 | 탭/버튼에 `aria-label`·`aria-expanded` 등 ARIA 속성을 부여하고 키보드 접근을 지원한다 |
| NFR-5 | 성능 | iframe은 `loading="lazy"`로 지연 로드하고, 첫 화면(축제)만 즉시 로드한다 |
| NFR-6 | 호환성 | 최신 Chrome·Safari·Edge 및 모바일 브라우저에서 동작한다 |
| NFR-7 | 유지보수 | 콘텐츠는 `assets/data/*.js` 데이터와 화면 로직(`assets/js`)을 분리해 관리한다 |
| NFR-8 | 폰트/언어 | UI 기본 언어는 한국어(`lang="ko"`)이며, 학습/동화 일부 콘텐츠는 영어를 포함한다 |
| NFR-9 | 저작권 | 상표·행사명·장소명의 권리 고지 및 정보 공유·개인 학습 목적 사용을 명시한다 |

## 6. 제약 사항 및 가정

- **정적 호스팅 전제**: 백엔드·DB가 없으므로 사용자 간 데이터 공유·동기화는 제공하지 않는다.
- **데이터 신뢰성**: 행사 정보는 외부 사정으로 변동될 수 있어 실시간 정확성을 보장하지 않는다(공식 출처 재확인 안내).
- **단일 기기 저장**: 기기·브라우저가 바뀌면 진행 상황이 이어지지 않는다.
- **콘텐츠 운영**: 행사 데이터 갱신은 운영자가 수동/스킬 기반으로 주기적으로 수행한다.
