## 1. 핵심 요약 (Top 3 기회)

| 순위 | 발견된 문제 | 영향 | 근거 위치 |
|:---:|------------|------|-----------|
| 1 | **마지막 본 탭이 기억되지 않음** — 새로고침 시 항상 '동네 축제'로 초기화 | 학습 중이던 부모·아이가 매번 처음으로 리셋 | `assets/js/pages/index.js` (기본 탭 고정) |

> **B7 설계 권장안**(실제 구현은 §13 참고)
> - **구현 방식**: 그림동화·코스와 동일하게 **별도 HTML 페이지**(`pages/family/festival-detail.html`)로 만들고, 카드 클릭 시 `?id=` 쿼리로 진입. 공유·북마크·뒤로가기 지원, `index.js`의 `kkoma:frame:*` 위치 저장과 자연 연동(모달 대비 권장).
> - **표시 정보**: 위치(기존 `location` + 네이버 지도 길찾기 재활용)·운영시간·입장료(`price`)·주차·예약방법·방문후기.
> - **신규 데이터 필드**: `hours`·`parking`·`reservation` 등을 `festivals.js`에 추가(값 없으면 "정보 없음" 표시), `update-festivals` 스킬로 점진 채움. 위치·입장료는 기존 필드 재사용.
> - **방문후기**: 정적 사이트·서버 없음 → **localStorage 기반 사용자 작성**으로 권장. 후기가 기기에만 남아 **봇의 무단 수집·스팸이 구조적으로 불가**하며, C4(백업/복원) 범위에 포함해 기기 변경 소실을 일부 보완. 운영 차원에서 `robots.txt`(AI 크롤러 차단, 적용 완료)·CDN 봇 보호를 병행.
> - **고유 ID**: 현재 카드는 배열 인덱스(`data-idx`)만 사용 → 데이터 순서 변경에 안정적인 식별자(예: `id` 필드 추가) 도입 검토.

## 5. 구현 완료 내역 — E1 PWA 전환 ✅

> 적용일: 2026-06-04 · 모바일 주 사용자(김서연 페르소나)의 **홈 화면 설치·오프라인 사용**을 목표로 PWA(Progressive Web App)로 전환 완료.

### 5.1 추가·수정 파일

| 파일 | 구분 | 내용 |
|------|:---:|------|
| `manifest.json` | 신규 | 앱 이름·아이콘·테마색(`#6B5B95`)·`display: standalone`·`start_url` 등 앱 메타데이터 |
| `sw.js` | 신규 | 서비스 워커 — **stale-while-revalidate** 캐싱(빠른 로딩 + 오프라인), 앱 셸 프리캐시, 오프라인 시 메인 폴백 |
| `assets/icons/favicon-64.png` · `icon-1024.png` | 신규 | 브라우저 파비콘 및 고해상도 PNG 앱 아이콘 |
| `assets/icons/icon-192.png` · `icon-512.png` | 신규 | 표준 PWA 아이콘(purpose `any`) |
| `assets/icons/icon-maskable-512.png` | 신규 | 안드로이드 적응형(maskable) 아이콘 |
| `assets/icons/apple-touch-icon.png` | 신규 | iOS 홈 화면 아이콘(180px) |
| `index.html` | 수정 | `manifest`·`theme-color`·`apple-touch-icon`·Apple 메타 추가, **CSP에 `worker-src`·`manifest-src`·`connect-src 'self'` 명시** |
| `assets/js/pages/index.js` | 수정 | 서비스 워커 등록 코드 추가(`navigator.serviceWorker.register('sw.js')`) |

### 5.2 동작 방식

- **홈 화면 설치**: 모바일 Chrome/Edge에서 "홈 화면에 추가" → 🎈 아이콘으로 전체화면 실행
- **오프라인**: 앱 셸(메인·축제·소개 등) 프리캐시 → 인터넷 없이도 열림. 방문한 페이지는 자동 캐시되어 재방문 시 오프라인 표시 가능
- **빠른 로딩**: 캐시 우선 응답 후 백그라운드 갱신(stale-while-revalidate)

### 5.3 검증 결과

| 점검 항목 | 결과 |
|-----------|:---:|
| `manifest.json` JSON 유효성(아이콘 4종) | ✅ |
| 아이콘 5개 파일 HTTP 200 서빙 | ✅ |
| `index.html` head 연결(manifest·theme-color·apple-touch) | ✅ |
| `index.js` 서비스 워커 등록 코드 | ✅ |
| 아이콘 디자인 육안 확인(보라 그라데이션 + 흰 풍선) | ✅ |

> 로컬 검증은 Node 정적 서버(`http://127.0.0.1`)로 수행. (이 PC의 `python`은 Microsoft Store 스텁이라 미사용)

### 5.4 운영 시 유의사항

- **HTTPS 또는 `localhost`에서만 동작** — `file://`로 직접 열면 서비스 워커가 등록되지 않음. 배포는 HTTPS 호스팅(GitHub Pages·Netlify 등) 필요.
- **콘텐츠 대규모 변경 시** `sw.js`의 `CACHE` 버전 숫자를 올리면 옛 캐시가 자동 정리됨.
- **CSP**: 기존 정책과 충돌 없음. 서비스 워커·매니페스트는 `default-src 'self'` 폴백으로도 허용되나 명시적으로 선언함.

## 11. 제약 및 고려사항

- **저장소 한계**: `localStorage`는 기기·브라우저 종속 → C4(내보내기/가져오기)로 보완, 완전한 동기화는 범위 외.

- **콘텐츠 신선도**: 축제 데이터는 운영자 수동 갱신 의존 → E5(자동 정리)로 노출 품질만 일부 자동화.
- **아이 사용성 우선**: 신규 UI는 "한 화면 핵심 행동 1~2개" 원칙(페르소나 3) 유지.

| `age` / `closed` | 대상 연령·휴관일 | 휴관은 실제 휴관 정보일 때만 표시 |
| `sourceUrl` / `verifiedAt` / `needsRecheck` | 출처·확인일·재확인 필요 여부 | 공식 URL과 변동 가능 문구 기준 자동 보강 |
| `temporarilyClosed` / `statusNote` | 임시 휴관·운영 중단 상태 | 목록/달력 일반 노출에서 제외하고 상세에서 경고 표시 |

> 데이터는 카테고리별로 공식 홈페이지·지도를 우선 확인해 채웠고, 미확인 값은 추측하지 않고 “공식 안내 확인 필요”로 보수적으로 표시한다. 변동 가능성이 큰 항목은 `needsRecheck`로 표시하고 상세 페이지에 출처·확인 상태를 함께 노출한다.

### 13.3 내 방문 후기(개인 기록형)

- 닉네임 없는 **단일 개인 기록**(별점 + 내용) — 저장 시 `내 후기` 배지와 함께 표시, **수정·삭제** 가능
- `localStorage`(`kidFestivalMyReview:<행사명>`)에 **이 기기에만** 저장 → 서버 전송 없음, 나만 봄
- 정적 사이트 구조상 **봇의 무단 수집·스팸이 구조적으로 불가**(서버에 후기가 모이지 않음)
